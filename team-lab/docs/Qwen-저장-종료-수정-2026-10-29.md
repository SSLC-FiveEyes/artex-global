# Qwen 결과 저장·작업 종료 수정

> 이 문서는 2026-10-29 당시의 수정·검증 기록이다. 최신 정리 상태와 남은 문제는 team-lab/README.md 및 Windows 브랜치 확인 안내를 따른다.

기준일: 2026-10-29 · 현재 배포: v0.3.15-global.1+completion.20261029.3

## 원인

원래 진단 #2에서는 Bash 성공 후 Qwen이 record_fact·prove_goal을 실제 호출하지 않고 예고 문장만 출력했다. 해당 worker 입력은 15,607토큰, 출력은 155토큰으로 32K 문맥·4096 출력 한도에 도달한 형태가 아니었다. 저장 API 호출 자체가 없었으므로 DB 쓰기 오류로 분류하지 않는다.

기존 ARTEX는 내용 있는 텍스트 응답을 자연 종료로 받아들였고, 빈 응답 복구만으로는 이 누락을 잡지 못했다. 또 실제 prove_goal 성공 뒤에도 모델의 추가 응답을 기다려 완료 상태 반영이 늦어질 수 있었다. 메인 에이전트에는 prove_goal이 기본 연결되지 않아 앞선 운영자의 직접 종료 지시도 부적절했다.

## 실제 코드 수정

- worker가 아무 결과도 저장하지 않고 끝내려 하면 이미 얻은 관측을 저장하도록 제한된 복구 지시를 보낸다.
- 복구 단계는 record_fact·report_finding·prove_goal과 사실 조회만 허용한다. 새 Bash·WebFetch·파일 변경·의도 생성 등은 실행 전에 차단한다. 반복된 금지 실행 시도도 중단한다.
- 복구 지시 횟수에는 상한이 있다. 끝까지 저장이 없으면 정상 done으로 분류하지 않고 실패로 반환한다.
- planner가 실제 근거를 가진 채 의도도 없이 멈추려 할 때 저장·상태 전환 복구를 적용한다. 프로그램이 근거를 만들어 넣거나 목표를 자동 승인하지 않는다.
- 실제 prove_goal 성공과 DB상 모든 목표 met를 확인하면 추가 모델 호출을 기다리지 않고 정상 종료한다.
- 정상 완료에 의한 내부 종료 원인과 사용자 중단·복구 실패 원인을 구분한다. 정상 완료가 화면에 ‘중단·미완료’로 표시되지 않도록 capture 경로도 수정했다.

변경 파일: agent/completion_contract.go, worker.go, planner.go, capture.go. 기존 권한·가로채기 훅은 유지한다. 저장 근거의 의미적 정확성까지 프로그램이 보장하는 것은 아니다.

원래 릴리스 소스 d6964594a0221cd921b85056d604bce9d8ce54df에 위 변경만 적용해 빌드했다. 현재 저장소 HEAD 전체나 다른 채팅의 UI 변경을 통째로 배포하지 않았다. 대시보드는 같은 릴리스의 정적 화면을 빌드했고, 런타임 도구·skills는 원래 고정 이미지의 것을 유지했다.

현재 로컬 이미지는 artex-local:completion-20261029-r3다. 실제 이미지·바이너리 SHA는 Git 제외 evidence/qwen-tool-fix-20261029/deployment.json에 보관했다. 관리 API health에서 보완 버전을 확인했다. DB 볼륨·로그인·127.0.0.1 포트는 유지했으며 코드 적용 전 SQL 백업을 남겼다. 커밋·푸시는 하지 않았다.

검사:

- 원래 릴리스 빌드와 현재 작업 소스에서 go test ./agent ./server -count=1 통과.

## 모델 설정 비교

지시문 보강만, 추론 low만, 비스트리밍 전환만으로는 누락·지연이 재발했다. 일부 중간 작업은 마감 정리 뒤 늦게 done으로 바뀌기도 했으므로 한 번의 성공만으로 설정 변경이 해결책이라고 결론 내리지 않았다. 최종 보완의 핵심은 위 실행 코드다.

현재는 같은 Q4_K_M 가중치를 재사용한 artex-qwen35-9b-q4km-32k-tools 별칭, 문맥 32768, reasoning_effort=low, streaming=true, 출력 상한4096을 사용한다. 생성값은 temperature0.6·top_p0.95·top_k20·presence_penalty0이다. [Qwen 공식 모델 카드](https://huggingface.co/Qwen/Qwen3.5-9B)의 정밀 코드 작업 권장값을 참고했다. 이 값이 단독 원인 또는 충분한 해결이라는 증거는 아니다. 추가 가중치 다운로드는 없었다.

관리 프롬프트도 worker의 실제 저장 확인, planner의 실제 prove_goal 확인, mainagent의 add_hint 전달로 보강했다. 공유용 qwen-completion-contract.example.json과 Modelfile.qwen3.5-9b-tools.example은 자동 적용 파일이 아니다.

## 운영·복원과 한계

기존 Mac 실행·종료 가이드의 Docker Compose 명령을 그대로 쓰면 현재 로컬 보완 이미지가 실행된다. Docker의 이미지 정리나 앱의 원클릭 업데이트로 보완 이미지를 제거·교체하면 이 수정이 사라질 수 있으므로 보완 바이너리와 소스를 비공개 evidence에 보관했다.

원래 이미지로 복원하려면 작업을 정지한 뒤 evidence의 compose-before-binary-fix.yaml을 config/compose.mac.local.yaml로 돌리고 같은 Compose 명령으로 실행한다. DB 스키마를 변경하지 않았으므로 일반적인 이미지 복원에 SQL 백업 복구는 필요하지 않다. 모델·프롬프트까지 원복하려면 같은 evidence의 before 스냅샷을 사용한다. 원래 모델 별칭과 가중치는 남아 있다.

이번 수정은 저장 누락·종결 처리 범위다. 홈페이지 전체 진단을 재실행하지 않았으며 취약점 판정 정확성·복잡한 다단계 공격·장시간 안정성·pfSense/Snort/Splunk 연계는 별도 검증이다. 모델이 근거를 잘못 해석하는 문제를 완전히 없앴다는 의미가 아니다.


## 실제 홈페이지 재시험에서 확인한 추가 경계 수정
