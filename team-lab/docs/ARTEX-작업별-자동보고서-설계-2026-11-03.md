# ARTEX 작업별 자동보고서 설계 초안

상태: 2026-11-03 소스 1차 구현. 완료·실패·시간 초과 시 생성 대기열, 작업별 LLM 초안·저장·실패 재시도 및 대시보드 링크를 추가했다. 실제 DB 마이그레이션·모델 호출·화면·서비스 배포 및 실측은 not_run. 일시정지는 종료로 취급하지 않는다. 기존 완료 작업은 자동 소급 생성하지 않는다.

## 목표

각 진단 작업이 완료·중지·실패·시간 초과로 끝나면 해당 작업의 실제 활동과 사실·발견을 바탕으로 보고서 초안을 저장하고 ARTEX에서 작업별로 읽는다. 작업의 종료 상태와 보고서 생성 상태를 독립적으로 표시한다. 재생성 시 기존 보고서를 덮어쓰지 않고 버전을 남긴다.

## 기존 기능과 한계

- 작업 상세의 보고서 탭은 `/api/report?task=...`로 생성한 Markdown을 표시한다. 현재 서버는 요청 시 작업 목표와 발견을 집계하며 별도의 작업 완료 보고서 저장 기능이 아니다.
- 기존 집계의 자산 수는 전역 자산이므로 작업에서 신규 발견한 수로 표시하지 않는다. 사실·실패·미실행 항목과 전체 활동 타임라인도 현재 종합 보고서에 충분히 반영되지 않는다.
- 취약점별 reporter는 별도 기능이다. 취약점이 없는 작업이나 중단된 작업에도 작업별 보고서가 필요하다.
- 기록된 성공적인 파일 저장은 보고서 내용의 진실성이나 탐지·차단을 보장하지 않는다.

## 보고서 내용

작업 ID·대상과 범위·시작/종료 및 종료 이유, 실험 설정과 한계, 요약, 시간순 시도와 도구 결과, 관찰 사실·추정·미확인, 발견별 증거와 영향·심각도 근거·개선 제안, 실패·미실행 항목, 관제 로그 대조와 탐지/차단 상태, 검토자 및 재시험 결과를 구분한다. 시간·요청·증거가 없으면 미확인으로 남기고 원문을 만들어내지 않는다. 관제 판정은 독립 로그를 연결하기 전까지 미확인이다. 인증값 등 민감 정보는 표시·내보내기 전에 제거한다.

## 구현 방향

1. 종료 시 해당 작업에 속한 활동·사실·발견과 상태를 서버가 모아 불변 스냅샷으로 저장한다. 관련 작업이나 전역 자산은 별도 출처로 명시하고 기본 합계에 섞지 않는다.
2. 생성 작업을 중복 방지 가능한 비동기 처리로 예약한다. 재시작·동시 종료·생성 오류에도 작업 상태와 별도로 대기/생성 중/완료/실패를 기록하고 수동 재시도를 제공한다. 중지·시간 초과 시에도 부분 결과로 생성한다.
3. AI는 스냅샷에 있는 사실을 근거로 서술 초안을 작성한다. 참조할 근거 ID가 없거나 모델 호출이 실패하면 그 사실을 표시하고 기록 기반 최소 보고서와 생성 실패 상태를 보존한다. 보고서 생성은 추가 대상 요청을 유발하지 않는다.
4. 작업 상세 보고서 탭에서 저장된 버전·상태·생성 일시와 본문을 보여주고 대시보드에 최근 작업별 보고서 목록과 상세 링크를 제공한다. 기존 동적 보고서와 구별한다. 재생성·검토·내보내기는 명시적 동작으로 둔다.
5. 빈 작업, 오류·중지·시간 초과, 동일 작업 중복 호출, 작업 간 자료 혼합, 재시작·재시도, 민감 정보 제거, 근거 없는 AI 주장 및 이전 보고서 보존을 격리 데이터로 검사한다. 실제 모델·UI와 Mac/Windows는 별도 검증한다.

## 미결정

모델 실패 시 저장된 입력 기록을 임시 보고서로 표시하고 재시도한다. 소스는 PoC 본문 및 일부 자격정보 패턴을 제거하지만 완벽한 비밀정보 제거를 보장하지 않으므로 검토가 필요하다. 선택된 모델이 원격 공급자면 처리된 작업 기록이 그 공급자에 전달된다. 저장 버전의 전체 목록·검토 이력 및 별도 내보내기와 정밀 마스킹은 미구현이다. 대시보드는 기존 작업 목록에서 최신 보고서 탭으로 연결한다. 실습 인프라·Splunk 연계 및 실제 공격은 이 작업 범위가 아니다.
