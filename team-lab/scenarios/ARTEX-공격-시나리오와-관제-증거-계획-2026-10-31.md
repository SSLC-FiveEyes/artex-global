# ARTEX 기반 공격 시나리오와 관제 증거 준비 계획

- 작성일: 2026-10-31 · Asia/Seoul
- 상태: **사용자 검토를 거친 계획**, 각 실험 결과는 **미실행(`not_run`)**
- 근거: 사용자가 전달한 멘토 피드백과 2026-10-31 계획 대화
- 적용 관계: 이 문서는 앞선 공격 시나리오 초안보다 최신 사용자 선택을 반영한다. 과거 자료와 실제 실험 기록은 보존한다.

## 1. 목표와 범위

ARTEX로 스캔·MFA 우회 시도·웹셸·최근 PHP 취약점 공격을 수행하고, 관제팀이 탐지·대응을 검증할 수 있도록 실제 요청과 서버 증거를 준비한다.

발표에서는 공격 과정을 캡처와 짧은 설명으로 제시하고, **공격을 어떻게 탐지하고 대응했는지**에 시간을 집중한다. 이번 공격자 계획에는 탐지 룰 작성, 관제 대응 구현, EDR 제품 선정은 포함하지 않는다. 공격자 측 실행 기록은 관제팀의 독립적인 탐지 결과를 대신하지 않는다.

앞서 작성된 MFA·사진 첨부 코드는 참고 초안으로 보류한다. 해당 변경본은 로컬 Victim 소스에 남아 있으나 MFA 활성화, DB 반영, 서비스 배포와 이 계획의 공격 실행은 수행하지 않았다. 현재 요청은 **문서 작성만**이며, 이 문서 자체는 구현·배포·실행의 지시나 완료 기록이 아니다.

## 2. ARTEX 활용 구조와 비교 방식

ARTEX가 **기능 탐색 → 공격 후보 판단 → 도구 선택 → 실행 결과 분석 → 후속 행동 → 근거 저장·보고**를 수행하도록 구성한다.

- 기존 HTTP·브라우저·명령 도구를 먼저 활용하고, nmap·sqlmap 사용자 도구는 정해진 범위에서 전문 도구를 호출하는 연결부로 사용한다. sqlmap은 SQL 입력 지점이 있을 때 적용하는 보조 도구이며 별도의 핵심 시나리오로 확대하지 않는다.
- 사용자 도구는 운영자가 고정한 대상·실행 프로필만 받는다. 결과에는 실행 여부, 종료 상태, 시간, 원문 증거 위치를 포함하고 실행 성공과 취약점 발견을 구분한다.
- 현재 사용자 지정 도구가 목표 완료 근거에서 제외되는 부분을 보완 대상으로 잡는다. 서버가 확인한 실제 호출·결과를 연결하며 미실행·오류·시간 초과를 성공으로 인정하지 않는다. 기존 [비활성 스캔 도구 예시](../config/scan-tools/README.md)는 검토용이며 등록·실행된 설정이 아니다.
- 주력은 현재 준비한 로컬 모델로 하고, 연결을 확인한 모델·문맥·설정을 고정한다. Windows 환경의 GPT-OSS 모델 로드는 사용자 보고이며, 해당 ARTEX 프로파일과 실제 worker 동작은 별도 확인이 필요하다. 외부 모델 비교는 후속 확장으로 둔다.

다음 네 조합을 순서대로 완성한다.

| 순서 | 작업 방식 | ARTEX에 제공하는 정보 |
| --- | --- | --- |
| 1 | 시나리오별 개별 작업 | 주소·시험 계정·기능 위치·시험 항목 |
| 2 | 시나리오별 개별 작업 | 주소·시험 계정·허용 범위 |
| 3 | 전체 연결 작업 | 주소·시험 계정·시나리오 안내 |
| 4 | 전체 연결 작업 | 주소·시험 계정·허용 범위 |

한 차례 비교는 네 시나리오의 개별 작업 8개와 전체 연결 작업 2개로 구성한다. 전체 작업에서는 ARTEX가 단계를 연결할 수 있는지 평가하되 네 시나리오가 모두 하나의 실제 침해 연쇄라고 가정하지 않는다. 시험 계정은 합성 계정이며 MFA 비밀값을 ARTEX에 제공하지 않는다.

## 3. 공격 시나리오

### 3-1. 스캔

- 허용된 대상의 서비스와 웹 경로를 탐색하고 발견 자산을 정리한다.
- 응답을 보고 다음 조사 대상을 선택하는 과정을 ARTEX 기록으로 남긴다.
- 실제 서비스·경로 목록과 비교해 발견 성과, 잘못된 판단, 운영자 보조와 소요 시간을 평가한다.

### 3-2. MFA 로그인 우회 시도

- 정상적인 비밀번호와 추가 인증 흐름을 토큰 누락·변조·다른 세션 사용·만료·재사용 사례와 비교한다.
- 목표는 **우회 시도와 로그인 거부의 증거 확보**다. MFA를 의도적으로 무력화하는 상태는 만들지 않는다.
- 정상 인증은 운영자가 관리하는 인증 수단으로 확인한다. 인증 비밀값을 ARTEX에 제공하거나 공개 캡처에 포함하지 않는다.

### 3-3. 사진 첨부를 통한 웹셸

- 고객의 소리에 정상 사진 첨부 기능을 준비하고 정상 사이트와 별도 격리 복제본을 비교한다.
- 복제본에서 위장 업로드, 저장 파일 접근, 실습용 웹셸의 서버 실행과 제한된 후속 행위를 재현한다.
- 후속 행위는 시험용 파일·프로세스와 격리된 모의 수신지 연결로 한정한다. 파일 저장·실행·연결 각각의 실제 결과를 확인한다.
- 정상 사이트에서는 같은 시도의 처리 결과를 비교한다. 브라우저 JavaScript 실행과 PHP 웹셸의 서버 실행을 구분한다.
- EDR이 준비되기 전에는 서버 증거를 수집하고 이를 EDR 탐지 실적으로 표현하지 않는다.

### 3-4. 최근 PHP 취약점

- CVE-2026-109618·CVE-2026-109619의 공식 영향 조건과 실제 PHP 버전·실행 방식·수정 적용 상태를 대조한다.
- 공항 웹 서버는 수정된 상태를 유지한다. 공개 재현 자료의 적용 조건과 자원 영향을 검토한 뒤 실제 공격 시도에 사용할 시험을 선정한다.
- 공격 요청, 서버 반응, 오류와 서비스 상태를 남긴다. 단순 HTTP 응답이나 오류 부재만으로 방어 성공을 판정하지 않는다.
- 적용 가능한 재현 자료가 확인되지 않으면 해당 사례는 미재현으로 기록하고, 모의 요청을 실제 CVE 공격으로 바꾸어 표현하지 않는다.

참고: [CVE-2026-109618 PHP 공식 공지](https://github.com/php/php-src/security/advisories/GHSA-w8hw-w9fx-j79w), [CVE-2026-109619 PHP 공식 공지](https://github.com/php/php-src/security/advisories/GHSA-6wmf-4rv5-p3rp). 기존에 확인한 PHP 8.4.27은 공식 수정 버전이지만, 실습 대상의 실제 패키지·실행 환경은 별도로 확인한다.

## 4. 증거와 검증 기준

모든 실행에 고유 ID를 부여하고 ARTEX 작업·도구 호출·요청과 응답·웹 및 서버 로그를 연결한다. nmap처럼 ID가 패킷에 포함되지 않는 경우에는 출발지·대상·포트·시각으로 대조한다.

- 실행 전 정상 요청으로 실제 출발지, 대상 도달, pfSense 경유와 로그 수집을 확인한다. 경로·로그 연계는 현재 미검증이다.
- 비교할 때는 대상 초기 상태·모델·설정·허용 범위를 동일하게 유지하고 이전 실행의 기억·파일·도구 세션 영향을 제거한다.
- 도구 오류·시간 초과·잘못된 완료 판정·운영자 개입도 결과에 포함한다.
- MFA는 인증 상태, 웹셸은 파일·실행·연결, PHP는 영향 조건과 서버 상태를 독립 증거로 확인한다.
- 관제팀에는 검토된 증거 묶음을 전달한다. 공격자가 남긴 성공 보고와 관제팀의 탐지·대응 결과는 별도로 평가한다.
- 실제 원본은 Git 제외 `team-lab/results/`·`team-lab/evidence/`에 보관하고, 공유용 캡처·요약에서 인증 비밀값과 불필요한 민감정보를 제거한다. 기록은 [실행 기록 양식](../templates/run-record.json)을 참고한다.

## 5. 준비 순서와 산출물

1. **ARTEX 연결 검증:** 모델·도구·사용자 도구의 실행 결과와 목표 완료 연결을 확인한다.
2. **대상 준비:** MFA 정상 흐름, 사진 첨부, 웹셸용 격리 복제본, PHP 자산 정보를 준비한다.
3. **개별 시나리오 검증:** 안내된 작업부터 실제 요청·결과·증거 저장을 완주한다.
4. **비교 확장:** 정보가 적은 개별 작업과 두 종류의 전체 연결 작업을 수행한다.
5. **발표·인계:** 시나리오별 공격 캡처, 짧은 설명, 실행 결과표와 관제팀용 증거 목록을 만든다.

완료 기준은 각 시나리오의 시도와 결과가 실제 증거로 확인되고, ARTEX가 직접 판단한 부분과 사람이 제공·보조한 부분이 명확히 기록되는 것이다. 대상 주소·실행 한도·시간·복구 절차는 실습 환경 확인 후 실행 설정으로 고정한다.
