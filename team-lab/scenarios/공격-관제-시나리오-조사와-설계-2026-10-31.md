# ARTEX 공격·관제 시나리오 조사와 설계

기준일: 2026-10-31 (Asia/Seoul) · 상태: 설계 초안 · 실행 결과: **not_run**

## 1. 목적과 현재 근거

가상의 공항공사 협력업무 포털에서 정상 업무와 공격 시도를 비교하고, 네트워크·웹·서버 증거를 연결해 관제 티켓의 분석·대응·재검증을 완주한다. ARTEX의 설명은 실행자 측 자료이며 관제의 독립 증거가 아니다. Kali·Metasploit은 별도 실행 도구다. 실행 능력이나 탐지 성과는 실측 전 확정하지 않는다.

Victim의 기존 문서에 따르면 공개 검색 `/search.php`, 로그인 `/login.php`, 구형 자료실 `/legacy/`, 권한이 필요한 `/download.php`가 있다. 구형 자료실은 현재 별도 서버가 아니라 같은 Apache/PHP의 논리 서비스로 설명되어 있다. baseline은 타 업체 문서를 거부하고 별도 `legacy-authz` 실습 상태는 구형 다운로드의 업체 범위 확인을 생략하도록 설계됐다. 이는 기존 문서의 설명이며 현 실습망의 설정·로그 연결을 확인한 결과가 아니다. 출처: [Victim 시나리오](../../../Victim/docs/scenario.md), [경로 목록](../../../Victim/docs/asset-paths-2026-10-30.md). 문서 링크는 양 저장소가 같은 부모 폴더에 있을 때 유효하다.

기존 검색 입력 제한 시험에서는 선택한 SQLi·반사 XSS 사례가 관측되지 않았다. 해당 시험은 운영자가 소스를 참고해 입력과 수집기를 설계했으며 전체 안전성이나 ARTEX 독립 탐색 능력의 증거가 아니다. [기록](../README.md)

## 3. 시나리오 카드

모든 카드 공통 상태는 `draft`, `not_run`이다. 대상 주소·계정·한도는 미정이다. 실제 실행 전 대상 소유자와 범위, 시간, 횟수, 중지 조건, 복구와 증거 보관을 정한다.

### S01 정찰: 구형 자료실 발견
- **전제**: 대상 서비스 목록과 공개 경로 정답표, 관측 지점 준비. ARTEX에서 지정 범위 밖으로 나가지 않도록 실행 방식 확인.
- **관측·가설**: pfSense 연결 기록, Snort 경보, Apache 경로·상태·시간을 대조한다. 여러 경로 탐색은 후보 신호이나 단일 수치 기준은 아직 없다.
- **대조와 판정**: 정상 공개 페이지 탐색 및 허가된 점검과 비교. 실제 경로 발견과 공격 탐지는 별도로 평가한다. 요청·서버 기록이 연결되지 않으면 판단 보류.

### S02 입력 공격 시도
- **전제**: 검색 등 입력 지점과 정상 동작을 확인하고 SQLi·XSS·경로 탐색을 각각 별도 실험으로 설계한다. 기존 검색에서 취약성이 확인됐다고 가정하지 않는다.
- **관측·가설**: 평문 HTTP의 경로·쿼리·본문 중 실제 Snort가 볼 수 있는 부분과 웹 응답, 앱 오류를 대조한다. 공격 유사 입력에 대한 경보는 시도 탐지다.
- **대조와 판정**: 정상 검색, 특수문자, 정상 다운로드를 포함한다. 취약점 성립은 독립적인 응답·서버·브라우저 근거가 필요하며 단순 경보는 성공이 아니다.

### S03 인증·객체 권한
- **전제**: 합성 A/B 계정과 서로 다른 소유 문서, baseline/별도 실습 상태, 로그인 결과와 권한 판단 로그의 필드를 확인한다. 기능·모드 변경은 별도 실행 단계다.
- **관측·가설**: 인증 실패 패턴과 타 업체 문서 요청을 웹·앱 로그 및 Snort에 대조한다. ID 변경만으로 권한 위반을 판단할 수 없다.
- **대조와 판정**: A 자기 문서 성공, A의 B 문서 요청, baseline 거부와 실습 상태 결과를 비교한다. 합성 문서의 실제 반환과 사용자·소유자·판정 근거가 있어야 권한 우회로 판정한다. 민감 데이터는 쓰지 않는다.

### S04 PHP CVE 영향 조사
- **전제**: PHP 패키지·배포사 백포트·실행 방식, 설정과 버전, 독립 실험 환경 가능성을 확인한다. 현 Victim의 기존 PHP 8.4.27 기록은 두 CVE의 공식 수정 버전이다.
- **관측·가설**: 비정상 multipart·오류·worker 이상은 일반적인 위험 징후 후보일 뿐 특정 CVE의 고유 서명이 아니다. PHP·Apache 오류, worker 상태 및 EDR 이벤트를 네트워크 기록과 대조한다.
- **대조와 판정**: 수정 전후 동일 조건과 정상 업로드·오류를 비교할 수 있는지 먼저 평가한다. 영향 조건과 독립적인 성공 근거가 없으면 미재현·판단 불가로 기록한다. 환경 구축·실행은 별도 지시가 필요하다.

### S05 웹셸 행위 모의
- **전제**: 업로드·파일 경로, 웹 서버 프로세스, EDR의 Linux 파일·프로세스·네트워크 수집 가능성 확인. 현재 업로드가 실행 가능하다는 근거는 없다.
- **관측·가설**: 격리 환경에서 무해한 모의 파일 생성과 접근, 허가된 모의 프로세스·연결 표식을 단계별로 비교하는 방안을 설계한다. Snort의 요청과 EDR 파일·프로세스는 별도 근거다.
- **대조와 판정**: 정상 게시물 첨부, 배포, 관리자 작업을 비교한다. 모의 행위의 관측은 실제 웹셸 설치나 CVE 악용 성공을 의미하지 않는다. 수집 누락 시 미탐과 관측 불가를 구분한다.

### S06 통합 관제 사건
- **전제**: S01·S03·S05 중 가능한 단계를 선정하고 각 단계가 이어졌다는 실증 근거를 확보한다. CVE 재현이 없으면 CVE 단계는 조사 배경으로만 표시한다.
- **관측·판정**: 아래 사건 흐름에 따라 경보부터 종결까지 추적한다. 인과관계가 확인되지 않은 이벤트는 같은 시간대의 별도 사건으로 남긴다.

## 5. 통합 사건과 관제 티켓

가상 설정: 담당자 이동 때 구형 자료실의 자산 정보와 점검 책임이 충분히 인계되지 않았다. 3년 이동 주기는 가상 기관 설정이며 실제 기관 전체의 규정이 아니다.

1. **정상 업무**: 협력업체가 자기 문서를 열고 담당자가 자료 이관 상태를 확인한다. 정상 요청과 권한 결과를 기준선으로 남긴다.
2. **발견**: 외부 역할의 실험자가 공개 경로를 살핀다. 관제는 네트워크 이벤트·웹 요청을 확인하고 자산 소유자를 찾는다.
3. **접근 시도**: 구형 자료실에 대한 타 업체 문서 접근이 발생한다. 관제는 계정·문서 소유권·응답 결과를 대조해 시도와 실제 노출을 구분한다.
4. **서버 행위 조사**: 별도로 준비된 모의 파일·프로세스 흔적이 있을 때만 EDR과 요청 기록을 연결한다. 모의 단계는 권한 우회나 CVE로 인해 발생한 실제 결과로 꾸미지 않는다.
5. **대응·검증**: 관제 담당자가 증거를 보존하고 서비스 소유자와 접근 제한·설정/패치 조치를 협의한다. 정상 업무 영향과 동일 조건 재시험으로 개선 여부를 확인한다.
6. **종결·인계**: 담당자, 자산·서비스 소유자, 남은 위험, 후속 점검을 기록한다. 실제 티켓 제품·자동화는 미정이다.

**티켓 예시 필드**: 사건 ID / 상태 / 탐지·발생 시각과 시간대 / 자산·서비스 / 담당자 / 경보 및 원본 링크 / 사용자·문서 소유권 / 시간순 증거 / 판단과 불확실성 / 대응 및 승인 / 정상 영향 / 재시험 / 종결·인계. 계정 비밀값과 원본 민감정보는 공유본에 넣지 않는다.

## 6. 수집과 Snort 규칙 개발·검증표

사전 확인은 별도 실행 지시 이후에 수행한다. 동일 실행 ID, 동기화된 시간과 시간대, 대상 서비스, 출발지와 NAT 전후 주소, 요청 식별자 또는 시간·경로·방향으로 증거를 연결한다. 각 소스에 실제 존재하는 필드만 사용한다. ARTEX ID가 패킷에 자동 포함된다고 가정하지 않는다.

| 단계 | 확인·기록할 내용 | 결과 |
| --- | --- | --- |

Snort는 패킷·스트림의 가시 범위를 검사한다. Snort 3와 2의 HTTP 규칙 문법이 다르므로 설치 버전을 확인한 후 작성한다. [Snort 3 HTTP 가이드](https://docs.snort.org/rules/options/payload/http/). EDR은 웹 서버 파일·프로세스 정보를 담당하고, Splunk는 실제 수집된 증거의 연관 분석과 티켓 연계를 지원한다. EDR 제품과 Linux 지원, 티켓 제품·연계 수준은 미정이다.

## 7. 준비 순서와 완료 기준

1. 팀이 대상·소유자·네트워크와 EDR 제품, 수집 필드를 결정한다. 현장 확인 전에는 미정으로 유지한다.
2. 정상 요청으로 경로와 수집을 검증한 뒤 S01과 S03의 정상·비정상 비교를 완주한다. 탐지 규칙이 어려운 권한 판단은 앱 로그와 결합한다.
3. S02의 입력 유형을 하나씩 조사·비교하고, 관측 증거가 충분한 네트워크 패턴부터 Snort 규칙을 개발한다.
4. S04는 영향·재현 가능성을 별도 판단하고, S05는 우선 무해한 모의 행위를 설계한다. 어느 쪽도 자동으로 이어진 것으로 표현하지 않는다.
5. 실제로 검증한 단계만 S06 사건과 티켓에 연결해 대응·재시험·인계까지 마친다.

완료 기준: 각 채택 사례의 조건·정상 대조·독립 증거·탐지 전후·판정 한계가 기록되고, 최소 하나의 실제 사건이 티켓 생성부터 재검증과 인계까지 증거로 추적된다. 현재는 계획이며 모든 실행·탐지·차단 성과는 미실측이다. 원본은 `team-lab/results/`, `team-lab/evidence/`에 보관하고 공유본은 검토 후 작성한다.
