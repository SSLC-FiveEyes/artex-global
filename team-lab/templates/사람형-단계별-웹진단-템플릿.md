# 사람형 단계별 웹 진단 — 작업 템플릿 초안

상태: 초안 · ARTEX 자동 등록 및 실행 안 됨 · 대상과 한도 미정

## 이름

사람형 단계별 웹 진단

## 설명

승인된 실습 웹사이트에서 한 번에 하나의 가설을 세우고, 정상 동작 확인 → 제한된 시도 → 응답과 로그 검토 → 다음 판단 순으로 진단한다. 시도 사이에 운영자가 정한 간격을 두고, 관제팀이 공격 흐름과 정상 활동을 비교할 수 있게 기록한다.

## 목표

승인된 실습 범위에서 웹 기능을 단계적으로 살펴보고, 관찰한 근거에 따라 취약점 가능성을 검증한다. 각 시도와 결과를 기록해 관제팀이 웹서버·Snort·Splunk 로그와 대조하고 탐지 규칙을 개선할 수 있게 한다.

실행 전 운영자가 작업에 지정할 값: 승인 대상과 경로, 허용 도구·행위, 최대 요청 수와 시간, 동시 작업 수, 요청 간 최소 간격, 중지 조건 및 실험 ID. 미지정이면 실행하지 말고 부족한 항목을 보고한다. 인증 정보는 별도 승인된 시험 계정만 사용한다.

1. 대상의 정상 기능과 응답을 먼저 확인하고 관측 사실을 기록한다. 승인 범위 밖 링크나 주소로 이동하지 않는다.
2. 관측을 근거로 확인할 가설 한 가지와 선택 이유를 기록한다. 여러 가설을 동시에 실행하지 않는다.
3. 해당 가설을 확인하는 데 필요한 최소한의 요청을 순서대로 수행한다. 요청과 다음 요청 사이에 지정된 최소 간격을 둔다. 시간·요청 예산과 중지 조건을 지킨다.
4. 각 응답을 살펴 정상 결과와 비교하고, 확인된 사실과 추정·자료 부족을 구분한다. 결과를 살펴본 뒤에만 다음 행동을 결정한다. 같은 요청을 근거 없이 반복하지 않는다.
5. 로그 대조에 필요한 실행 시각, 도구, 대상 경로, 요청 목적, 응답 상태와 실행 ID를 기록한다. 비밀번호·세션 값·인증 토큰은 보고서에 기록하지 않는다. 실행 ID가 모든 장비 로그에 자동 삽입된다고 가정하지 않는다.
6. 서버 오류가 지속되거나 한도에 도달하거나 운영자가 중지하면 즉시 멈춘다. 완료하지 못한 항목은 미실행 또는 미확인으로 남긴다.
7. 실제 관찰과 별도로 Snort 경보, 차단, Splunk 수집 여부는 독립 로그와 담당자 확인 전까지 미확인으로 표시한다. 취약점 확인, 공격 시도, 탐지, 차단을 서로 같은 결과로 취급하지 않는다.

## 적용 메모

- ARTEX 템플릿 관리의 이름·설명·목표 필드에 각각 복사하는 초안이다. 범위와 숫자는 실제 환경 검증 후 운영자가 정한다.
- 이 문구는 모델에 주는 지침이다. 지연, 요청 횟수, 동시성, 대상 제한을 강제로 보장하지 않는다. 실행 환경에서 별도 통제·계측하고 실제 로그로 확인한다.
- 시간 간격을 둔다고 실제 사람과 구분되지 않는 것은 아니다. 사람의 실제 정상 행동 로그를 별도로 확보해 비교한다.
- 네트워크 경로, pfSense 경유, Snort와 Splunk 수집은 검증 전이다. 이 템플릿의 작성이나 등록은 대상 실행 승인이 아니다.
