# 반복 실행과 보고서 준비

현재는 구조와 기록 양식만 준비했다. 자동 실행 프로그램·예약 작업·대상 요청은 만들거나 실행하지 않았다.

향후 자동화는 실행 조건 확인 → 대상과 ARTEX 상태 초기화 → 단일 작업 실행 → 증거 수집 → 서버 측 판정 → 결과 요약 순서로 설계한다. 모델 호출 실패와 실제 공격 실패를 구분하고, 다른 모델로 자동 전환된 실행은 단일 모델 비교에서 제외한다.

첫 검증은 단일 작업과 worker 1개로 진행한다. 정상·공격 요청의 지속 반복은 예비 검증을 통과한 다음 실행률·동시성·비율·보존량·중단 기준을 정해 확장한다. 설치·실행을 진행하라는 사용자 요청이 있기 전까지 실행 스크립트와 스케줄러를 추가하지 않는다.

기록 양식은 `templates/run-record.json`, `templates/run-summary.csv`, `templates/report.md`다. 실제 값은 실행 후 채우며 매 실행의 대상·유형·일자·결과를 연결한다. 공통 보고서 양식과 작성 주기는 팀 협의 사항이다.
